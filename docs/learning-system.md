# 学習の仕組み（v0.2.0：Lemma に寄せたもの）

GAIA v0.2.0 は、学習の進め方・記録の守り方を [Lemma](https://github.com/kurowasan3/lemma)（v0.27）と同じ仕組みにした。
探究（5ページ）と問題データの形は GAIA のまま。Lemma の「解法カード」にあたるものは、GAIA では **概念**（`content/concepts.json`）。

| Lemma | GAIA | 主なファイル |
|---|---|---|
| 解法カード（76枚） | 概念（61個）。問題の `concepts` の先頭が主な概念、残りが補助。必須の前提は `requires` | `js/catalog.js` の `conceptIndex` |
| 解法の習熟（未学習・学習中・要復習・習得・転用） | 概念の習熟（同じ基準） | `js/mastery.js` |
| 解法カードのページ（`#tech=`） | 概念のページ（`#concept=`）。使う法則・よくある誤解・習熟・問題 | `js/app.js` の `renderConcept` |
| 頻出度（管理表の列・自動判定） | 頻出度（`problem.json` の `frequency`。無ければ主な概念の問題数から自動） | `tools/build_data.py` |
| 選択式の選択肢（`tools/make_choices.mjs`） | 同じ考え方。語句は用語のつながり（対比）と同じ単元の用語、数値は2倍・半分などの取り違え | `tools/make_choices.mjs` → `content/choices.json` |
| 記録の保全（`js/store.js`）・同期の分類・サーバー側の制限（`guard.sql`） | 同じ（表 `gaia_state`・エラーは `GM00x`） | `js/store.js`・`js/sync.js`・`supabase/guard.sql` |

## 今日の学習（ホーム）

- 今日解いた数／目標（1回分の問題数）。連続日数は出さない（煽らない）。
- **前回の続き**：中断した演習を、答え終えた問題の次から再開（端末の中だけ。`gaia.session.v1`、2週間で捨てる）。
- **今日の演習を始める**（`catalog.js` の `pickToday`）：選んだ規則を理由として問題ごとに表示する。
  1. 復習の時期が来た問題（新しい学習の枠を最低3問残す。復習が1回分の4倍より多くたまったら2問）
  2. 要復習の概念から最大2問 → 3. まだ学んでいない概念（先に学ぶ概念を学び始めているもの）から1問
  4. 完答した概念を違う文脈（別の単元・ほかの概念も関わる問題）で1問 → 5. 苦手な単元から最大2問 → 6. 新しい問題（頻出度の高いものほど選ばれやすい）
  - 復習以外は1つの単元から1回の3分の1まで、復習と合わせて半分まで。足りないときは少ない数で出して理由を表示。
- はじめての人には「まず8問解いてみる」（基礎〜入試基礎）だけを大きく出す。
- 架空の学習者8人での確認：`node tools/simulate_recommend.mjs`（テストは `tests/recommend.test.mjs`）。

## 解答後

- 自己採点のボタンは左から 不正解・一部正解・完答（良い方が右）。
- 自信度×結果：正解だが「自信なし」→ ヒントありと同じ短い間隔で復習。「確実」なのに不正解 → 思い込みの注意と核となる考え方を表示。
- 主な概念が「浮かんだか」を任意の1タップで記録（`r`）。概念のページから解いた回は `k: 't'`（知らされて解いた）。
- **類題を1問追加**：同じ単元・難易度の差1以内で、主な概念が共通（タグ3つ分）・共通のタグが多い・未着手の問題を次に差し込む。
- ★ ブックマーク（外したときも `on:false` を残し、同期でよみがえらない）。

## 解答の形式（設定）

- **記述式**（既定）：語句・数値を入力して自動採点。選ぶ・並べる欄はもともと選んで答える。
- **選択式**：語句・数値の欄も4択（`content/choices.json`）。やり直しなし。正解しても「確実」での復習間隔は記述式より短め。
- **自己採点**：答え合わせで自分で採点。
- 記録の各回に形式 `md`（input・choice・self）を残す。

選択肢の作り方（`node tools/make_choices.mjs`、`--check` で検査）：

- 語句：手で書いた誤りの選択肢（`answer.parts[].distractors`）→ 用語のつながりで「対比」の相手 → 同じ単元で正解とつながっていない用語 → 同じ単元の別の問題の答え。
  「例・部分・関連」でつながる用語は上位の分類や言いかえで正解とも言えることがあるので使わない。時刻・方位・走向・傾斜・回る向きは同じ形の語どうしだけ。
- 数値：2倍・半分・10倍などの組（正解だけが真ん中にならない組を問題ごとに決まった手順で選ぶ）。有効数字で丸めて正解と重ならないもの。
- どれも、アプリと同じ採点（`checkField`）で必ず不正解になることを確かめる。作れない欄は入力のまま。

## 頻出度

`problem.json` の `frequency`（1=低・2=中・3=高）。省略すると、主な概念を扱う問題の数から自動で決める（10問以上＝高・5〜9問＝中・4問以下＝低。全体のおよそ3割・5割・2割）。
よく使われる考え方ほど問題集・入試に繰り返し出る、という近似で、入試の出題数を数えたものではない。手で直すときは `frequency` を書く。

## 定着度

- 得意・苦手は1つの単元で5問以上から（10問未満は「暫定」）。最近2週間とそれ以前の完答率（どちらも10回以上のとき）。
- 「次にやること」（判定保留・最近の低下・たまった復習・要復習の概念・転用・想起）。
- 概念の習熟（状態ごとの数・分野ごと・要復習・次に学ぶとよい概念）と、判定の基準。

## 学習記録の保全（`js/store.js`）

Lemma v0.23〜v0.26 と同じ規則。仕様の詳細は Lemma の `docs/data-integrity.md`。

- 読めない記録は上書きせず `gaia.v1.broken.<時刻>` に退避。保存に失敗したら前の記録のまま。容量不足では控えを捨てて本体を優先。
- 同じ端末の別のタブの保存とは、合わせてから保存（`storage` イベントでも合わせる）。
- 移行・読み込み・すべて消す の前に、控え（`gaia.snap.v1`、最大2件）を残す。設定の「自動の控え」から戻せる。
- `schema` は 4（v0.1 の記録は 1 か 4。形は同じなので印だけ進める）。schema を上げるときは保存先のキーも変える。
- バックアップ（`gaia-backup` v1）：形式・版・作成時刻・件数・確認用の値（FNV-1a）を確かめてから、今の記録と「合わせる」か「置き換える」かを選ぶ。
- すべて消す：消した印 `resetAt` を付ける（同期で、ほかの端末・サーバーの古い記録を持ち込まない）。ログイン中は「この端末とアカウント」か「ログアウトしてこの端末だけ」を選べる。
- ログイン直後、端末とアカウントの両方に記録があるときだけ、合わせるか・アカウントの記録だけを使うかを聞く。ログアウトのときにこの端末の記録を消せる（送れたことを確かめてから）。

## 同期とサーバー側の制限

- 同期の失敗を分類（通信・同時の書き込み・サーバーの不調は間をあけてやり直す、サーバーに断られた・記録の形の問題は自動の同期を止める）。
- `supabase/guard.sql`：表 `gaia_state` への書き込みごとに、解答の記録・復習状態・ブックマーク・メモが消えていないか、版番号・schema・resetAt が正しいかを確かめて、破る書き込みを断る（`GM001`〜`GM009`）。
  **Supabase の SQL Editor で `schema.sql` のあとに1回実行が必要**（何度実行してもよい。既存の記録は変えない）。適用済みかは `select gaia_private.guard_version();`（`gaia-0.2.0`）。
- 検査：`tests/server_guard.test.mjs`（PGlite。`npm install --no-save --no-package-lock @electric-sql/pglite` があるときだけ `run.mjs` が実行）。

## 配信（`tools/build_dist.py`）

`python3 tools/build_dist.py` で、アプリが動くのに必要なファイルだけの `dist/` を作る（`content/`・`tools/`・`tests/` などは入れない）。
`_headers`（CSP などのセキュリティヘッダー）と `robots.txt` を足す。`node tests/e2e_dist.mjs` が CSP つきで配信して動くかを確かめる。
`.github/workflows/ci.yml` は push のたびに `node tests/run.mjs --e2e` を実行し、`CF_PAGES_PROJECT` などを登録すれば main への push で Cloudflare Pages に配置する（登録しなければ検査だけ）。
